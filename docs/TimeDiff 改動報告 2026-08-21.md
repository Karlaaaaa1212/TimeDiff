# 從原始 TimeDiff 到現在的版本

**日期** 2026-08-21 ｜ **視窗** seq_len 63 → pred_len 21 ｜ **測試期** 2020-01-02 ~ 2024-12-31（1258 天）
**資料** 10 檔美股 × 3 通道（close / high / low 對數報酬），訓練 2008-2017

---

## 摘要

原始 TimeDiff 到現在的版本，一共動了三個地方：

| # | 名稱（學界通用） | 改在哪一層 | 解決什麼 |
|---|---|---|---|
| 1 | **條件變數 c**（scalar conditioning variable）+ **conditioning dropout** | 輸入 | 讓模型可以被指定要生成什麼情境 |
| 2 | **v-prediction**（velocity parameterization, Salimans & Ho 2022） | 訓練目標 | 修正「模型退化成條件均值」 |
| 3 | **Classifier-free guidance**（Ho & Salimans 2022） | 採樣 | 讓條件變數真的被服從 |

### 六個組合的實測（20 樣本 × 59 個不重疊區塊）

| 模型 | 條件 | 交出 σ | gain | 波動比 | **樣本間離散** | 最壞日 σ | 超額峰態 |
|---|---|---|---|---|---|---|---|
| 原始 TimeDiff | 無 | −0.322 | — | 0.11 | **0.02** | −0.32 | 0.73 |
| 原始 TimeDiff | c = −3 | −1.212 | 0.30 | 0.12 | **0.02** | −0.54 | 0.23 |
| 原始 TimeDiff | c = −3, w = 5 | −4.635 | 1.44 | 0.58 | **0.09** | −2.37 | −0.04 |
| + v-prediction | 無 | −0.226 | — | **0.89** | **0.88** | −1.94 | 0.00 |
| + v-prediction | c = −3 | −0.974 | 0.25 | **0.89** | **0.88** | −2.10 | −0.01 |
| **+ v + CFG** | **c = −3, w = 5** | **−3.619** | **1.13** | **0.95** | **0.90** | **−2.82** | −0.06 |
| *真實市場* | — | — | — | *1.00* | *1.00* | *−2.16* | *14.6* |

- **交出 σ**：模型實際產生的 21 日累積移動，以標準差為單位
- **gain**：`(交出 − 無條件基準) / 要求值`。1.0 表示條件被完全服從
- **樣本間離散**：不同噪聲種子產生的路徑彼此差異 ÷ 真實波動。**這是判斷模型有沒有在生成分布的關鍵指標**

## 一、原始 TimeDiff 是什麼

### 兩個條件

TimeDiff 的核心設計是**非自迴歸**的條件擴散：不逐步生成，而是一次產出整段未來，靠兩個條件把資訊帶進去。程式碼在 `DDPM_modules/DDPM_CNNNet.py:275-296`：

**(a) Future mixup**（`L289-293`）— 訓練時把「從歷史線性投影出的預測」與「真實未來」以隨機比例混合：

```python
        rand_for_mask = torch.rand_like(y_clean)
        pred_out = rand_for_mask * pred_out + (1 - rand_for_mask) * y_clean
```

推論時 `y_clean=None`，只留下線性投影。這是一種 scheduled-sampling 式的訓練技巧，縮小訓練與推論之間的落差。

**(b) 自迴歸初始化**（`L295`）— 一個預訓練的 DLinear 給出整段未來的初步估計，當作另一路條件：

```python
        ar_init = cond_info[:, :, self.ori_seq_len:self.ori_seq_len + self.pred_len]
        inp = torch.cat([x, pred_out, ar_init], dim=1)
```

### 訓練目標與採樣器

- **參數化**：`x_start`（網路直接預測乾淨訊號 `x0`）
- **噪聲排程**：cosine，100 步
- **採樣器**：DPM-Solver（Lu et al. 2022），20 步，二階 multistep，確定性 ODE（`eta=0`）

### 原始版本**沒有**的東西

- 沒有任何可指定的條件變數
- 沒有 conditioning dropout
- **CFG 的混合演算法在 `dpm_solver.py` 裡（函式庫自帶，從未改動），但永遠不會被執行**：因為沒有條件可引導，`unconditional_conditioning` 恆為 `None`，`dpm_solver.py:337` 的短路判斷永遠成立

> 這一點先前的報告寫得不精確。正確說法是：**CFG 的機器一直都在，但沒有東西可以引導**。它能被啟用，是加入條件變數帶來的結果。

## 二、改動 1：條件變數 c + conditioning dropout

### 為什麼要改

原始 TimeDiff 只能回答「接下來最可能怎麼走」。壓力測試需要的是**反事實查詢**：「如果接下來 21 天發生 3 個標準差的暴跌，各檔股票的路徑會長什麼樣」。這需要一個可以從外部指定的條件。

### 怎麼改

定義一個純量條件變數，每個通道一個：

```
c = sum(未來 21 天的標準化報酬) / sqrt(21)
```

除以 `sqrt(21)` 是為了讓它在 i.i.d. 假設下服從 N(0,1)，也就是「幾個標準差」的直接解釋。

**(1) 架構留位置** — `DDPM_CNNNet.py:242-248`

條件以「值 + mask」兩欄表示，所以每個變數多兩個通道：

```python
        knob_channels = 2 * self.num_vars if self.use_knob else 0
        self.combine_conv = InputConvNetwork(
            args, self.dim_intermediate_enc + self.num_vars + knob_channels,
            self.num_vars, num_layers=args.ddpm_layers_II)
```

這一行決定 checkpoint 的形狀，所以開關不同的權重不能互換。

**(2) 前向時攤平** — `DDPM_CNNNet.py:298-301`，純量複製成 `pred_len` 長度再與時間序列串接。

**(3) 訓練** — `DDPM.py:178-180`，teacher forcing 加隨機遮蔽：

```python
            knob = self.knob_from_future(x_dec_i[:, -self.args.pred_len:, :])
            mask = self.knob_dropout_mask(knob.shape[0], knob.shape[1], knob.device)
            x_past = self.attach_knob(x_past, knob, mask)
```

### 為什麼要這樣改

**為什麼用 mask 而不是只放值**：「沒有條件」必須是一個明確的 token，而不是「值等於 0」——後者會跟「要求 0 個標準差的移動」混淆。

**為什麼要 conditioning dropout（`knob_p_uncond = 0.15`）**：這是 Ho & Salimans (2022) 的標準訓練配方。15% 的機率整筆遮掉，讓**同一份權重同時學會條件模式與無條件模式**。

> 這個 15% 看似小事，**卻是第三項改動能成立的唯一前提**。沒有無條件模式，CFG 沒有基準可以做對比外插。

### c = −3 在統計上站得住嗎

| ticker | c 的實測 sd | −3 相當於幾個實測 sd | 訓練窗口 ≤ −3 | **不重複事件** | 隱含 21 日跌幅 |
|---|---|---|---|---|---|
| AAPL | 1.02 | −2.94 | 39 | 5 | −22.5% |
| AMGN | 0.87 | −3.43 | 2 | **2** | −19.8% |
| CRM | 0.89 | −3.39 | 20 | 2 | −29.2% |
| CSCO | 0.89 | −3.37 | 8 | 3 | −22.2% |
| IBM | 0.91 | −3.31 | 18 | **1** | −17.0% |
| INTC | 0.88 | −3.39 | 11 | 7 | −21.5% |
| MSFT | 0.82 | −3.68 | 3 | 3 | −20.6% |
| NKE | 0.81 | −3.70 | 6 | 4 | −20.8% |
| VZ | 0.88 | −3.42 | 6 | 3 | −16.5% |
| WMT | 0.84 | −3.59 | 7 | 4 | −14.8% |

**兩個必須揭露的限制：**

1. 實測 sd 是 **0.81–1.02**，不是理論的 1.0（21 日加總有輕微負自相關）。因此 −3 對 MSFT 是 −3.68 個實測 sd、對 AAPL 只有 −2.94，**同一個數值對不同標的代表不同的嚴重程度**。建議改用各通道的實測 sd 標準化。
2. 2497 個訓練窗口中 ≤ −3 的僅 0.08%–1.6%，且滾動窗口高度重疊，**換算成不重複的市場事件只有 1–7 個**（IBM 僅 1 個）。**指定 c = −3 屬於外插**，主要評估應使用 −1.5 / −2。

## 三、改動 2：v-prediction

### 為什麼要改

原始 TimeDiff 有一個嚴重但不易察覺的問題：**擴散過程實質上失效**。

| 量測（20 樣本 × 59 區塊） | 原始 TimeDiff |
|---|---|
| 樣本間離散 / 真實波動 | **0.02** |
| 波動比 | 0.11 |
| 最壞單日 | −0.32σ（真實 −2.16σ） |
| 20 樣本取平均後 MSE 改善 | **0.0%** |

最後一列是決定性證據。若樣本彼此獨立，取平均會顯著降低誤差；實測毫無改善，代表 **20 條路徑實質上是同一條**。

**機制**：在 `x_start` 參數化下，網路的訓練目標是 `x0`。給定條件 `c` 後，`x0` 與含噪輸入 `x_t` 在統計上獨立，因此網路可以完全忽略 `x_t`，直接輸出 `E[x0 | 條件]`——而 MSE 損失獎勵的正是條件均值。

`x_t` 是採樣過程唯一的隨機性來源。它被忽略，模型就退化成一個確定性的回歸器。

### 怎麼改

擴散前向過程為

```
x_t = sqrt(a_t) * x0 + sqrt(1 - a_t) * eps ,    eps ~ N(0, I)
```

（`a_t` 為 alpha_bar_t）。改用 Salimans & Ho (2022) 的 **v-prediction**，訓練目標為

```
v_t = sqrt(a_t) * eps - sqrt(1 - a_t) * x0
```

**反解推導**：將前向式乘 `sqrt(a)`、v 的定義乘 `sqrt(1-a)`，相減消去 `eps`：

```
sqrt(a) * x_t - sqrt(1-a) * v = (a + 1 - a) * x0 = x0
```

得 `x0 = sqrt(a) * x_t - sqrt(1-a) * v`，**兩個係數皆 ≤ 1，不含除法**。

**程式碼四處**：

| 檔案 | 改動 |
|---|---|
| `diffusion_worker.py:195-213` | 新增 `get_v()`（訓練目標）與 `predict_start_from_v()`（採樣反解），**必須成對** |
| `diffusion_worker.py:175` | 訓練 target 加 `"v"` 分支；另有 assert（L46）、`lvlb_weights`（L124）、ancestral sampler 三處小改 |
| `samplers/dpm_sampler.py:75` | `model_type` 由寫死的 `"x_start"` 改為 `self.diffusion_worker.parameterization` |
| `DDPM.py:47`、`config.py` | 放行 `"v"`，並在 help 說明各參數化的風險 |

> `dpm_sampler.py` 那一行最容易遺漏。DPM-Solver 內建支援 `"v"`，但原本寫死為 `"x_start"`；只改訓練不改採樣，v 訓練出的網路會被當作輸出 `x0` 來解讀，產出無意義的結果（已實測驗證）。

### 為什麼選 v 而不是 eps

`eps`（noise prediction）同樣能堵住捷徑——目標含 `eps`，而 `eps` 只能從 `x_t` 得知。但本專案的排程使它無法使用。

這是文獻中已知的 **zero terminal SNR** 問題（Lin et al. 2024）。本專案的 cosine 排程在終點的實測值為 `a_T = 2.43e-7`，因此

```
1 / sqrt(a_T) = 2029
```

`eps` 的 `x0` 還原式需除以 `sqrt(a_t)`，在最後一步會把網路的預測誤差**放大 2029 倍**。

**實測驗證**：eps 版本的 test RMSE 為 **1899**，訓練殘差約 0.94，而 `0.94 × 2029 ≈ 1907`——數量級與數值皆吻合。這不是訓練失敗，是還原步驟在數值上必然發散。

三種參數化的比較：

| | 目標與 `x_t` 相關？（堵住捷徑） | `x0` 還原的誤差放大倍率 |
|---|---|---|
| `x_start` | **否** | 1 |
| `eps` | 是 | **2029** |
| **`v`** | **是** | **≤ 1** |

**只有 v 同時滿足兩個條件**，這是選擇它的完整理由。

### 效果

| | 原始 TimeDiff | **+ v-prediction** |
|---|---|---|
| 樣本間離散 / 真實波動 | 0.02 | **0.88** |
| 波動比 | 0.11 | **0.89** |
| 最壞單日 | −0.32σ | **−1.94σ**（真實 −2.16σ） |
| 20 樣本平均後 MSE 改善 | 0.0% | **36.7%** |
| test MSE（單樣本） | 1.115 | 2.085 |

**單樣本 MSE 變差是預期結果。** MSE 是 proper scoring rule 中獎勵條件均值的一種；原始版本因退化而恰好輸出條件均值，等於**以放棄生成能力換取 MSE**。v 每次抽取的是預測分布中的一個樣本，單樣本自然離實現值更遠。

> 因此 v-prediction 之後不應再以單樣本 MSE 作為主要指標，應改用 **CRPS** 等分布層面的 proper scoring rule。

## 四、改動 3：Classifier-free guidance

### 為什麼要改

條件變數單獨使用時力道嚴重不足：

| | gain | 要求 −3σ，實際交出 |
|---|---|---|
| 原始 TimeDiff | 0.30 | −1.21σ |
| + v-prediction | 0.25 | −0.97σ |

條件確實有作用（方向正確），但幅度只有要求的四分之一到三分之一。

### 怎麼改

CFG（Ho & Salimans 2022）在每個採樣步同時計算條件與無條件預測，再外插：

```
輸出 = 無條件輸出 + w * (條件輸出 - 無條件輸出)
```

`w = 1` 退化為純條件預測，`w > 1` 放大條件的影響。

演算法本身在 `dpm_solver.py:336-344`（函式庫自帶，未修改）：

```python
elif guidance_type == "classifier-free":
    if guidance_scale == 1. or unconditional_condition is None:
        return noise_pred_fn(x, t_continuous, cond=condition)
    else:
        x_in = torch.cat([x] * 2)
        c_in = torch.cat([unconditional_condition, condition])
        noise_uncond, noise = noise_pred_fn(x_in, t_in, cond=c_in).chunk(2)
        return noise_uncond + guidance_scale * (noise - noise_uncond)
```

**需要接的線**（`DDPM.py:240-244, 264-265`）：

```python
        guidance, cond_null = 1.0, None
        if self.use_knob:
            x_past, cond_null = self.knob_tensors(x_past, knob)   # 條件 / 無條件兩份
            if knob is not None:
                guidance = float(getattr(self.args, 'knob_guidance', 1.0))
        ...
                    unconditional_guidance_scale=guidance,
                    unconditional_conditioning=cond_null if guidance != 1.0 else None,
```

第二段是原本沒力的原因：**預設 `w = 1.0` 時連 `cond_null` 都不傳**，`dpm_solver` 直接短路成單次推論。

### 為什麼用 CFG 而不是直接放大條件值

直覺上，要更強的效果只要把 `c` 從 −3 改成 −15。實測顯示這條路不可行：

| 設定 | 交出 σ | gain |
|---|---|---|
| 無條件 | −0.233 | — |
| c = −3 | −0.960 | 0.24 |
| c = −6 | −1.341 | 0.18 |
| c = −10 | −1.442 | **0.12** |
| c = −15 | −2.133 | 0.13 |
| c = −30 | −4.170 | 0.13 |
| **c = −3, w = 5** | **−3.640** | **1.14** |

**兩個理由：**

**(1) 條件反應飽和。** gain 從 0.24 衰減到 0.12，效率減半。要達到 −3σ 需將 `c` 開到 −20 以上。

**(2) 外插的位置不同。** 這是更根本的差異：

- **放大 `c`** 是在**輸入空間**外插。訓練資料中 `c` 的實測範圍約為 ±6.5，`c = −30` 落在網路從未見過的輸入區域，其 embedding 未經訓練，行為無理論保證。
- **CFG** 是在**輸出空間**外插。兩次前向的輸入皆在分布內（`c = −3` 見過、無條件 token 在訓練中出現 15%），放大是兩個良定義預測之間的線性運算。

> 溫和放大（`c = −6`）仍在資料支撐範圍內，是可接受的折衷；超過 ±6.5 則不建議。

### 效果，以及為什麼三項改動缺一不可

| 模型 | w = 1 → w = 5 | gain | 波動比 | **樣本間離散** |
|---|---|---|---|---|
| 原始 TimeDiff | −1.212 → −4.635 | 0.30 → **1.44** | 0.12 → 0.58 | 0.02 → **0.09** |
| + v-prediction | −0.974 → −3.619 | 0.25 → **1.13** | 0.89 → 0.95 | 0.88 → **0.90** |

兩者的 gain 都被拉到 1 以上（原始版甚至超調至 1.44），但**樣本間離散揭露了本質差異**：

- 原始 TimeDiff + CFG 的離散僅 **0.09**——CFG 把那條唯一的路徑變得更陡、更不平滑，看起來像市場，但所有樣本仍幾乎重合。它提供的是**單一情境**，不是情境的**分布**。
- v-prediction + CFG 的離散為 **0.90**——條件被服從，且服從的是一整個分布。

**三項改動正交，各自解決一個問題：**

```
條件變數 c   →  決定「要什麼」        （輸入層）
v-prediction →  決定「有沒有分布」    （訓練目標層）
CFG          →  決定「力道多大」      （採樣層）
```

實測佐證：v 沒有改善 gain（0.30 → 0.25），CFG 沒有改善離散（0.02 → 0.09），條件變數不影響波動比（有無條件皆 0.89）。

## 五、尚未解決

| 問題 | 目前 | 真實市場 |
|---|---|---|
| **厚尾** | 超額峰態 −0.06 ~ 0.73 | **14.6** |
| **波動叢聚** | 區塊波動追蹤 corr 0.24 | 1.00 |

v-prediction 修復的是**平均波動水準**，生成的是變異數正確的近高斯序列。真實報酬的超額峰態 14.6 意味著極端日的頻率遠高於常態分布，而模型的峰態近乎 0。

`path_volatility_check_by_ticker.png` 呈現得最清楚：真實序列有 COVID 尖峰（AAPL 104%、INTC 135%）與 2022 年的高波動期，模型則是一條近乎水平的帶——它輸出的是**平均波動**，而非**時變波動**。

兩者同源：缺少**波動叢聚（volatility clustering / GARCH 效應）**。下一步的波動匹配損失目標應改寫為「讓條件變異數隨輸入變化並具備厚尾」，而非單純提高波動水準。
